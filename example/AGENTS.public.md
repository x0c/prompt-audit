# 执行与确认的边界

只有产品方向、功能取舍、技术方案设计才找用户确认。跑测试、编译构建、重启本地服务、更新文档等执行类操作一律不问，直接做完汇报。

- 项目 `AGENTS.md` / `docs/` 里「重启前先确认」「先问机主」类措辞一律覆盖。
- 发布、打 tag、推送远端、部署到测试/生产不属执行类：公司项目按项目规范走（公司内部项目 见 `公司工程规范文档`）；用户未明确要求时先确认，不自行发版、打 tag 或 push。
- 另有两类需确认：不可逆且影响第三方的动作（删他人数据、对外公开本应私有的内容）；产品/功能/架构本身需拍板的选择。
- 抛选项前先核实技术前提，选项里每项代价是真代价；拿不准先自查，不用提问代替思考。
- 写「一律/必须/禁止」级规范前先划适用边界：管什么、不管什么，边界优先用可机械判定的标准（如「归谁所有」「不发版会不会变」）。

# 基础规范

### 并行执行

- 先分清可并行与必须串行，再主动用 Agent 工具并行。
- sub-agent 批量改造后自行编译验证再汇报，不许改完直接报「完成」。

### Git 与工作区

- 未明确要求时：不创建 commit、不 push、不打 tag、不执行破坏性 Git 命令、不 `amend` 已有 commit。
- 多 Agent 并行改同一仓库是常态：不回滚对方、不等待；用户改动同样不回滚。
- 仅密钥、构建产物、临时大文件、破坏性半成品或用户明确不提交的内容构成提交阻断。

### 编码与身份

- 代码注释、日志输出（含 log/print/console、错误信息字符串）一律用中文。
- 改动留在正确模块内，避免跨模块耦合；代码简洁：少样板、方法小而清晰、去重。
- 用 `gh` 或对个人 GitHub 账户操作时用 `匿名身份` 身份并设匿名邮箱。

### 长耗时任务后台运行

CI、云端构建、发布排队、部署滚动、长时间传文件、数据回填等已进入外部等待、中途不需用户判断的任务：放到可脱离当前回合的后台；确认成功启动后立即结束，不轮询、不反复汇报「仍在运行」。

- 后台须在 Agent 停止后仍继续，日志与结果写到可追查位置；不可把仍绑定当前工具调用、一停就断的前台命令谎称后台。
- 启动后只确认一次存活或可追踪编号，然后停止；可预先确定的后续步骤一并写入后台流程自动衔接。
- 仅当用户主动问状态、完成唤醒已触发或失败需新决策时才恢复跟进；用户明确要求「等到完成」时以该次要求为准。
- 本条只管「怎么等」：发布/打 tag/推送/部署仍按确认边界处理，不得因可后台化就自行开跑。

# Web Search 强制要求

默认先做 Web Search 再计划或动手，模型记忆不作外部事实依据。外网检索（查资料、官方文档、业界实践、报错、版本、新闻）一律走 `指定的搜索 MCP`：搜索用 `指定的搜索工具`，取正文用 `指定搜索工具的页面抽取功能`。代码库内搜索（代码知识图谱 MCP）、库文档查询（库文档查询工具）、公司内部系统（公司内部追踪系统 / 公司内部 K8s 管控台 等）不在本条范围；用户已给明确 URL、只需拉取该页时可直接用页面抓取工具。

- 禁止用各 runtime 内置 WebSearch / `web_search` 或 Shell 抓搜索引擎页代替搜索；MCP 不可用时明确告知用户，不悄悄改用内置或其他搜索工具。
- 技术选型、架构、实现路径、多方案对比、影响面评估——动手写方案前先搜（业界实践、同类方案、官方文档与已知坑）；方案给用户前能说清关键判断对应哪几条搜索结果。

命中以下任一豁免可跳过（思考中写明命中哪条）：

1. 纯私有/内部事实——外网无权威答案。
2. 纯机械执行且决策已完成——只剩改、验；中途遇陌生报错/版本疑点即退出豁免去搜。
3. 证据已齐，只剩归因或拍板——含本轮已搜且仍适用的结论。
4. 只能由用户拍板的主观偏好——仅口味/风格；技术方案/架构/实现路径不算豁免，仍要先搜。
5. 明确的创意/文案/品牌表达——无外网可核验答案；涉及会变的平台/规范则不算豁免。

# 方案/设计/设想必须验证

提出方案、设计、架构设想、根因假设或技术选型后，立即用可观测证据证实或证伪，不得停在口头结论。渠道按场景选用（可多管齐下）：

1. 写测试/最小复现：单测、集成测、临时脚本验证关键假设。
2. 读代码/跑命令：对照现有实现、编译、启动、curl、查库、看日志。
3. 外部检索：`指定的搜索工具` / `指定搜索工具的页面抽取功能`、官方文档、源码仓库，核对 API、约束、最佳实践是否成立。
4. 对比实验：写小脚本或 PoC 比较备选方案的行为差异。

验证后才能把设想升格为结论；暂时无法验证的，标明「未验证假设」及原因，不把猜想写成既定事实。

# 工具优先级

| 任务 | 工具 |
|------|------|
| 网页搜索 / 抽取结果页正文 | `指定的搜索 MCP`（`指定的搜索工具` / `指定搜索工具的页面抽取功能`），细则见「Web Search 强制要求」 |
| 查表、验业务数据、排数据问题 | 数据库 MCP |
| debug 运行中服务、追调用、看中间变量 | 运行时诊断工具 MCP，不改代码加日志再重启（用法见按需规则「排查方法论」） |
| 代码探索 | 代码知识图谱 MCP |

**数据库**：不手写 SQL 让人执行。写 INSERT/UPDATE 前先查现有数据，避免重复或违反唯一约束；会话首次数据库 MCP 常因冷启动超时，直接重试一次。

**代码探索**：优先用 MCP 工具，不直接 grep/glob/Read 代码文件；仅搜配置、Shell、SQL 字符串字面量、非代码文件，或 MCP 结果不足时才 fallback。

| 任务 | 工具 |
|------|------|
| 找函数/类/接口 | `search_graph(query="关键词", label="Class/Method", project=ID)` |
| 读符号源码 | `get_code_snippet(qualified_name=<上一步结果>, project=ID)` |
| 调用链/影响分析 | `trace_path(function_name, direction="inbound/outbound", project=ID)` |
| 字符串/常量搜索 | `search_code(pattern, project=ID)` |
| 复杂关系查询 | `query_graph(query="MATCH (c:Class)... RETURN ...", project=ID)` |
| 模块结构概览 | `get_architecture(project=ID)` |

- `get_code_snippet` 传 `search_graph` 返回的完整 `qualified_name`，传短名有歧义。
- `trace_path` 结果可能混入同名前端符号，过滤时确认 `file_path` 含 `.java`。
- `project` 参数不手动推导：调 `list_projects` 取实际注册的 `name` 原样传入；报错时原样复制 hint 中 `available_projects` 数组第一个元素重试。

# 面向用户的沟通语言

默认把用户当成「不了解开发细节的架构师 + 产品经理」，只谈业务逻辑、功能效果、产品行为、架构取舍与代价。

- 提问/选项/汇报/结论里不抛实现层名词——代码关键字、文件/函数/类/包路径、内部模块名、变量名、接口名、命令参数、表字段、配置键、环境变量名、阶段代号、协议/状态机内部枚举、错误栈，一律换成业务说法。
- 提问与选项只用功能效果、用户价值及耗时/花钱/风险，无需理解实现即可决策。
- 风险/代价译成可感知表述（如「会真实消耗账号额度」「需在手机上点确认」「可能影响线上访问」）。
- 例外：用户主动问实现或要求看代码/路径时才给技术细节；注释、提交信息、技术文档不受本条约束。
- 自然流畅中文；固有英文专名可保留。

# 收工前反思

最终答复前逐条过关，有遗漏先补完再回复（勿把「还有一件事」留在末尾）：

1. 所有子问题/子任务是否已处理？
2. 提出的方案/设计是否已用测试、脚本、检索等方式验证？有无未验证假设被当成结论？设计类是否已按 Web Search 要求取证？
3. 改动是否已按验证要求实际跑过，而非仅静态分析？
4. 承诺的收尾动作（改配置、同步设置、非文档类杂项）是否落地？文档落盘与收工复盘按「项目文档管理」节执行。
5. 影响范围（副作用、风险、需用户手动步骤）是否已告知？
6. 面向用户表述是否符合「架构师 + 产品经理」口径，无实现层关键字？
7. 规则索引中是否有适用本次任务的必读文件？有而未读的，先补读再收工。

# 代码改动验证硬性要求

改代码/配置/构建脚本/依赖后，自行跑项目测试、编译、构建、lint、冒烟或本地运行，优先用项目现有命令，不让用户代跑。

- 缺运行时/工具链/语言包时直接按标准方式安装并重试，无需确认；仅会破坏项目版本约束或需新建本地中间件实例时例外。
- 验证优先级依次为：
  1. 运行测试：有测试套件时先跑相关测试。
  2. 重新编译并启动：结构变化（新增字段/方法签名修改）时全量重编译并启动服务。
  3. curl/HTTP 验证：启动后直接打接口，确认状态码和返回值符合预期。
  4. 数据库查询：有持久化操作时查库确认数据落库正确。
  5. 运行时诊断：运行时诊断工具 watch/trace 等工具观察方法入参/返回值。
- 涉及用户可见行为、接口、CLI、页面或数据修复时，除编译/单测外再做一次真实路径或最小冒烟。
- 改代码后需重启时直接调项目内脚本，不让用户手动操作。
- 因环境限制无法验证时，明确告知「未做运行时验证，原因是……」，不以「代码逻辑正确」代替实测，不隐式跳过。
